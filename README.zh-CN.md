# QAgent

[English](README.md) | [简体中文](README.zh-CN.md)

QAgent 是一个面向中文使用场景的轻量 Chatbot 原型。它结合了确定性的意图路由、简单工具、内存内短期对话历史和基础文档问答。

> QAgent 目前还不是自主 Agent。每次请求只执行一个预定义分支；模型不会自主规划多个步骤、任意选择工具、等待人工审批或恢复长时间任务。

## 项目状态

QAgent 是一个仍在开发中的学习和实验项目，适合本地演示与架构实验，但还不是可供多用户使用的生产级服务。

项目保留 **QAgent** 名称，表示未来可能的演进方向，并不表示当前实现已经具备自主 Agent 能力。

## 当前能力

- 面向中文场景的普通 LLM 问答。
- PDF、TXT、Markdown 文档上传和文本提取。
- 基础文档问答和文档总结。
- 基于 Python AST 白名单的简单安全计算。
- 由 LLM 解释导数、积分和极限问题。
- 固定模板提纲生成。
- 内存内短期对话历史。
- 可显示路由和检索细节的 Streamlit 聊天界面。

## 为什么它还不是 Agent

当前程序是一个使用确定性路由的工具增强型 Chatbot。每次请求执行哪个分支，由应用代码决定，而不是由模型自主决定。

目前尚未实现：

- 模型驱动的工具选择；
- 多步规划或工具执行循环；
- 观察工具结果后的动态重新规划；
- 高风险操作的人工审批；
- 任务状态持久化、暂停恢复和失败恢复；
- 执行预算、最大步数和工具权限。

## 系统架构

```text
用户输入
  ↓
Streamlit UI 与会话状态
  ↓
基于关键词的 Router
  ↓
一个预定义工作流分支
  ├─ 计算器
  ├─ 数学解释
  ├─ 提纲生成
  ├─ 文档问答
  └─ 普通问答
  ↓
LLM 回答
  ↓
更新记忆和 UI
```

所有工作流分支都返回相同的数据结构：

```python
{
    "route": str,
    "answer": str,
    "retrieval_mode": str,
    "retrieved_chunks": list[str],
}
```

## 当前 Router 规则

规则严格按以下顺序执行：

| 优先级 | 条件 | Route |
|---:|---|---|
| 1 | 包含“积分”“导数”或“极限” | `math` |
| 2 | 去除可选的计算请求用语后，是有效的纯算术表达式 | `calculator` |
| 3 | 已加载文档，且命中总结词、显式文档词或文档指代词 | `document_qa` |
| 4 | 包含“提纲”或 `outline` | `outline` |
| 5 | 其他情况 | `general_qa` |

计算器规则要求同时出现数字和算术运算符。单独出现 `/` 或 `-`、URL、`2026-07-13` 这类日期、版本号，以及仅在自然语言中包含这些字符的文本，都不会触发计算器。这种设计速度快、行为透明且容易测试，但对未列关键词、歧义问题和不同表达方式仍不够稳健。

## 当前 RAG 流程

```text
PDF/TXT/Markdown
  → 文本提取
  → 固定字符分块
  → 字符/关键词评分
  → 上下文截断
  → LLM 回答
```

Streamlit 上传流程调用 `chunk_text(text, chunk_size=800, overlap=120)`。当前检索属于词面检索：它根据完整 query、中文字符重合或英文空格分词进行评分，不是基于 Embedding 的语义检索。

当前 RAG 限制：

- chunk 是裸字符串，没有来源、页码、章节或稳定 ID；
- PDF 页码元数据没有保留；
- 回答不包含来源引用；
- 没有 BM25、Embedding、向量数据库、混合召回或 reranker；
- `rag/index.py` 目前为空；
- 尚未使用评测数据集衡量检索质量。

## 安装

建议使用 Python 3.10 或更高版本。

```powershell
git clone https://github.com/PooooLish/QAgent.git
cd QAgent
python -m pip install -r requirements-dev.txt
```

如果只安装运行环境，可以改用 `requirements.txt`。

## 配置

启动应用前，在当前进程环境中设置 `OPENAI_API_KEY`。不要把真实值提交到 Git。

当前默认模型是 `gpt-4o-mini`，在 `app.py` 创建 `GeneralQAAgent` 时指定。

`Memory(max_turns=8)` 保留最近 8 条消息，而不是 8 个完整的用户/助手回合。进程重启后，对话状态不会保留。

## 使用方式与示例问题

启动应用：

```powershell
streamlit run app.py
```

示例：

- 普通问答：`什么是机器学习？`
- 文档问答：上传文件后询问 `这个文档的主要结论是什么？`
- 文档总结：`总结这份文档的主要内容`
- 提纲：`生成一个深度学习学习提纲`
- 计算器：`计算 2^10 + 24`
- 数学：`解释 x² 的导数`

## 测试

仓库包含 7 个测试文件和 17 个离线测试，覆盖路由、计算器安全、文本分块、词面检索、LLM 消息构造、数学工作流返回值和临时文件清理。

```powershell
$env:PYTHONDONTWRITEBYTECODE = "1"
python -m pytest
```

测试不会调用真实 OpenAI API，也不会启动 Streamlit 浏览器。它们验证已实现的程序行为，不验证回答或检索质量。

## 当前限制

- 关键词路由可能错误分类改写表达和混合意图问题。
- 文档问题如果不含已识别的文档关键词，可能不会进入 RAG。
- 当前是词面检索，不是语义检索。
- 回答没有来源引用或依据评分。
- 对话和文档状态只保存在内存中。
- 没有流式输出、重试、超时、取消、token 统计或可观测性。
- 上传文件没有生产级大小、页数、MIME 或解析时间限制。
- 没有用户认证、权限控制或多用户数据隔离。
- 没有真正的 Agent Loop 或自主多工具执行。

## 推荐演进路线

1. 引入包含来源、页码、章节和稳定 ID 的结构化 chunk。
2. 增加依据引用和证据不足时的明确拒答。
3. 建立小型检索评测集，记录 Recall@k 和 MRR。
4. 将当前词面检索基线与 BM25、向量检索和混合检索比较。
5. 增加持久化、流式输出、超时、重试和基础可观测性。
6. 只有在真实多步用例出现后，才加入受控 Agent 工具循环。

## 安全与隐私

- 不要提交 API Key、`.env`、上传文档、日志、缓存或本地私有文档。
- 把上传文档文本视为不可信输入。
- 不要直接执行模型生成的代码。
- 测试保持离线，并使用非私人测试数据。
- 生产使用前需要增加文件限制、用户隔离、工具权限和审计日志。
