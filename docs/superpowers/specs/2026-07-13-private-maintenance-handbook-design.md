# QAgent 私有维护手册设计

## 目标

为项目所有者和后续编码 Agent 创建一份详尽、可维护、中文的项目解释手册。手册必须保存在 QAgent 任务目录内，但不得被 Git 跟踪、提交或推送。

## 交付形式

- 私有正文路径：`docs/private/QAgent项目维护手册.md`
- 正文格式：UTF-8 Markdown
- 保密标记：文档标题后明确标注“私有、本地、禁止提交”
- Git 策略：在 `.gitignore` 中加入 `docs/private/`
- 版本控制：只提交 `.gitignore` 规则；私有正文始终保持未跟踪且被忽略

## 目标读者

手册同时服务于：

1. 项目所有者：理解当前能力、限制、运行方式和演进方向。
2. 后续编码 Agent：快速掌握规则、代码结构、数据流、验证方式和禁止事项。

正文不假定读者已经熟悉 Agent、RAG、Streamlit 或 OpenAI SDK。首次出现的关键术语必须用中文解释，并在术语表中给出简短定义。

## 内容结构

手册采用单文件、稳定编号的章节结构：

1. 文档属性与使用规则
2. 项目定位和成熟度
3. 能力边界与非目标
4. 技术栈与目录结构
5. 系统架构和核心数据流
6. 模块与关键函数逐项说明
7. Streamlit 会话和文件上传生命周期
8. 路由、工具、Prompt、LLM 和记忆机制
9. 文档摄取、分块、检索和回答生成
10. 配置、安装、启动和常用操作
11. 测试体系及各测试文件的保障范围
12. 安全、隐私和数据处理边界
13. 已知限制、技术债与故障模式
14. 调试和故障排查手册
15. 日常维护 SOP
16. 推荐演进路线和阶段完成标准
17. 交接清单、术语表与常用命令

## 内容原则

- 以当前仓库实际代码为准，不把未来规划写成已经实现的能力。
- 每个模块说明其职责、输入、输出、依赖、失败方式和维护注意点。
- 所有本地文件引用使用仓库相对路径，避免移动任务目录后链接失效。
- 命令以 Windows PowerShell 为主，并说明是否会修改环境或外部状态。
- 避免复制大段源码；使用短小伪代码、流程和接口说明解释行为。
- 对已知限制给出影响、识别方式和建议处理顺序。
- 演进路线必须有进入条件和完成标准，避免无边界的功能清单。
- 文档中不得包含真实密钥、token、密码、私人上传内容或机器敏感配置。

## 可维护性机制

- 文档开头记录“代码基线提交”和“最后核对日期”。
- 章节标题使用稳定编号，便于跨会话引用。
- 增加“变更触发矩阵”，规定修改路由、Prompt、RAG、文件处理、测试或依赖时必须同步更新哪些章节。
- 增加“事实、限制、规划”三类标记，避免读者混淆当前实现与未来建议。
- 每次重大代码修改后运行文档核对清单，而不是要求正文自动生成。

## 验证

完成时必须验证：

1. `git check-ignore -v docs/private/QAgent项目维护手册.md` 命中 `.gitignore`。
2. `git status --short --ignored` 显示私有目录为 ignored，而不是 untracked 或 staged。
3. 文档为 UTF-8，可由 PowerShell 正确读取。
4. 文档中不存在待补内容标记、未解释占位符或真实凭据。
5. 章节覆盖设计列出的 17 类内容。
6. 文档描述的测试数量、文件结构、路由和功能与当前代码一致。

## 非目标

- 不创建 Word、PDF 或在线文档副本。
- 不把私有正文提交到 GitHub。
- 不在本轮修改业务源码、依赖或测试。
- 不自动采集或写入本机环境变量、API 密钥和用户上传文档。
