# QAgent 核心缺陷修复设计

## 目标

修复当前原型中五个已经确认、可独立复现的问题，使数学问答、文档总结、LLM 消息、README 计算示例和上传临时文件生命周期符合项目说明，同时保持现有架构与用户界面不做无关重构。

## 范围

本轮修复：

1. 数学路由执行后没有返回结果。
2. 已加载文档时，总结类问题仍进入普通问答。
3. LLM 消息列表可能包含 `None`，并把系统提示重复拼入用户消息。
4. README 示例使用 `^` 表示指数，但计算器不支持该输入。
5. 上传文件读取完成或发生异常后，临时文件未清理。

本轮不实现 `rag/index.py` 中预留的向量索引，不增加向量数据库、Web 搜索、CI 或其他新功能。

## 设计

### 工作流返回契约

`GeneralQAAgent.run()` 的每条路由都返回包含 `route`、`answer`、`retrieval_mode` 和 `retrieved_chunks` 的字典。数学路由沿用 LLM 推导提示，返回 `retrieval_mode="none"` 和空检索列表，不改变其他路由行为。

### 文档总结路由

当 `has_document=True` 且问题命中已有总结关键词时，路由到 `document_qa`。计算、数学和提纲等明确工具意图保持更高优先级，避免“总结 2+2”之类输入错误进入文档检索。总结关键词保持单一来源，由路由层定义并供工具层复用，避免两处列表逐渐分叉。

### LLM 消息构造

当存在系统提示时，消息顺序为一个 system message 和一个 user message；user 内容只包含调用方传入的 prompt。当没有系统提示时，只发送一个 user message。任何情况下消息列表都不包含 `None`，也不重复系统提示。测试使用假的 OpenAI 客户端，不读取环境密钥、不发网络请求。

### 计算器指数兼容

计算入口在 AST 解析前把 `^` 规范化为 `**`，使 README 示例得到 `1048`。求值仍只允许现有 AST 运算符白名单；函数调用、属性访问等表达式继续返回统一失败信息。

### 临时文件生命周期

在 `utils/file_utils.py` 增加“保存上传对象、读取文档、始终清理”的单一接口。该接口在 `finally` 中删除自己创建的临时文件；读取成功和读取抛错两条路径都保证清理。`app.py` 不再直接管理 `NamedTemporaryFile`，只调用该接口。删除仅限该接口刚创建并持有的临时路径，不接收任意用户路径作为清理目标。

## 错误处理

- LLM API 异常继续向上抛出，本轮不新增重试或吞错逻辑。
- 计算器对不受支持或无效的表达式继续返回“计算失败，请检查表达式”。
- 文档解析异常继续向 UI 传播，但临时文件必须先清理。
- 临时文件清理使用缺失容忍方式，避免清理阶段掩盖原始解析异常。

## 测试策略

每个缺陷严格执行红—绿循环：

- 工作流测试用伪 LLM 和伪内存复现数学分支返回 `None`。
- 路由测试复现已加载文档时的总结请求误路由，并验证工具优先级。
- LLM 测试绕过构造器注入伪客户端，断言传给 SDK 的完整消息列表。
- 计算器测试以 README 的 `2^10 + 24` 为回归用例，并保留恶意表达式拒绝测试。
- 文件工具测试使用临时目录和伪上传对象，分别覆盖读取成功与读取异常后的清理。

完成后运行全部 pytest 测试、Python AST 解析、Git 差异检查和敏感文件名检查。测试不得调用真实 OpenAI API 或启动 Streamlit 服务。

## 文档与状态

- README 保留 `2^10 + 24` 示例，因为修复后该示例可运行。
- `task.md` 将五项已知问题移入已完成记录，并把向量索引保留为后续工作。
- 不把真实密钥、上传文件、日志、缓存或临时文件加入版本控制。

## 完成标准

- 五个回归测试在修复前分别因目标缺陷失败，在修复后通过。
- 全部离线测试通过，无网络调用。
- `GeneralQAAgent.run()` 对所有现有路由保持统一返回结构。
- 文档读取成功或失败后均不存在本次调用创建的临时文件。
- 业务源码差异仅涉及 `agent/llm.py`、`agent/router.py`、`agent/tools.py`、`agent/workflow.py`、`utils/calculator.py`、`utils/file_utils.py` 和 `app.py`。
- `task.md` 与实现状态一致，Git 工作区无生成文件或敏感数据。
