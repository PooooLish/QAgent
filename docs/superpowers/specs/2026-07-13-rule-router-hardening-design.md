# QAgent 规则 Router 加固设计

## 目标

在保持 `route_query(query: str, has_document: bool = False) -> str` 兼容接口的前提下，提高确定性 Router 对算术、数学、文档问答、文档提纲、普通提纲和普通问答的分类准确性。路线 2 的结构化 `RouteDecision` 是后续目标，本轮不改变调用方接口。

## 当前问题

1. 单个 `-`、`/` 等字符就会触发计算器，导致 URL、英文连字符和 A/B 表述误判。
2. “计算 x 的导数”先命中“计算”，错误进入计算器。
3. 已加载文档时，“作者、本文、这篇、这份、章节、结论、实验”等指代不进入文档问答。
4. “给这份文档生成提纲”先命中提纲规则，无法根据文档内容回答。
5. 所有规则集中在 `route_query()`，难以独立测试和为未来结构化决策复用。

## 设计

### 规范化

新增 `normalize_query(query: str) -> str`，执行 `strip()` 和 `lower()`，其他判断函数只接收规范化后的字符串。函数保持无副作用。

### 算术识别

新增 `is_calculator_query(query: str) -> bool`：

- 允许可选控制词，如“计算”“算一下”“等于多少”。
- 去除控制词后，表达式必须至少包含一个数字和一个算术运算符。
- 剩余字符只允许数字、空白、小数点、括号和 `+ - * / ^ %`。
- URL、英文单词、`A/B`、版本号说明和连字符文本不得进入计算器。
- 该函数只负责意图识别；实际安全计算继续由 AST 白名单负责。

### 数学识别

新增 `is_math_query(query: str) -> bool`，识别“积分、导数、极限”。数学意图在计算器之前判断，使“计算 x 的导数”进入 `math`。

### 文档识别

新增三类常量：

- 明确文档词：`文档、pdf、文章、材料、论文、文件`
- 文档指代词：`作者、本文、这篇、这份、其中、章节、结论、实验`
- 总结词：保留现有 `SUMMARY_KEYWORDS`

新增 `is_document_query(query: str, has_document: bool) -> bool`。只有 `has_document=True` 时返回真；命中总结词、明确文档词或文档指代词均视为文档请求。

### 提纲冲突

新增 `is_outline_query(query: str) -> bool`。优先级规定：

1. 数学
2. 有效算术表达式
3. 已加载文档且明确引用文档
4. 普通提纲
5. 普通问答

因此：

- “生成深度学习提纲” → `outline`
- “给这份文档生成提纲”且已有文档 → `document_qa`
- 同一句话在没有文档时仍回退到 `outline`

### 兼容接口

`route_query()` 继续返回现有五种字符串：

- `calculator`
- `math`
- `outline`
- `document_qa`
- `general_qa`

`agent/workflow.py`、`app.py` 和工作流返回契约不变。

内部判断函数保持小而独立，以便路线 2 后续复用这些判断结果构造 `RouteDecision(route, confidence, reason, matched_rules)`。

## 测试策略

使用 pytest 表驱动测试，至少覆盖以下类别：

- 正常算术：纯表达式、中英文控制词、括号、小数、幂。
- 算术负例：URL、A/B 测试、英文连字符、普通斜杠文本、仅数字。
- 数学：积分、导数、极限及“计算导数”冲突。
- 文档：明确文档词、总结词、作者/本文/章节/结论/实验指代。
- 文档负例：无文档时相同指代不得进入 `document_qa`。
- 提纲：普通提纲和“文档提纲”冲突。
- 默认普通问答。

总路由样本不少于 30 条。每个新判断函数有直接测试，`route_query()` 有端到端优先级测试。

## 错误和边界

- 空字符串返回 `general_qa`。
- 仅有数字但无运算符返回 `general_qa`。
- 无文档时，文档指代词不触发 `document_qa`。
- 混合意图仍只选择一个 route；本轮不实现多工具执行。
- 不使用 LLM、网络或外部分类服务。
