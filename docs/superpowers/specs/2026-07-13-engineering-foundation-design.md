# QAgent 工程化基础设计

## 目标

在不修改业务逻辑的前提下，将 QAgent 整理为可持续开发的半成品任务：明确任务状态和局部协作规则，隔离生成文件，并建立无需 API 密钥即可运行的基础测试。

## 范围

本轮新增或调整以下工程资产：

- `task.md`：记录任务目标、当前状态、已知问题、完成标准和常用验证命令。
- `AGENTS.md`：补充仅适用于 QAgent 的开发与安全约束，不弱化工作区根规则。
- `.gitignore`：忽略 Python 字节码、测试缓存、虚拟环境、本地环境变量、日志、临时文件和用户上传内容。
- `tests/`：加入 pytest 离线测试，覆盖路由、计算器、文本分块和检索等不依赖外部服务的现有行为。
- `requirements-dev.txt`：声明 pytest 开发依赖，不污染生产依赖。
- Git 索引：停止跟踪已有 `__pycache__` 和 `.pyc` 文件，保留源码与目录结构。

本轮不修复数学工作流返回值、文档总结路由、OpenAI 消息构造、临时文件清理或 `^` 运算兼容性，也不安装依赖、不调用外部 API、不配置 CI。

## 文件职责

- `task.md` 是半成品状态的唯一任务级登记入口。
- `AGENTS.md` 约束后续代理先读任务文档、使用测试驱动修复业务问题，并禁止真实密钥进入仓库。
- `.gitignore` 只处理本地或生成内容，不隐藏需要版本控制的源码、测试和文档。
- `tests/` 记录当前已经成立的离线行为；已知缺陷只登记，不写成预期通过的测试。
- `requirements-dev.txt` 提供可复现的最小测试依赖入口。

## 验证策略

1. 在未安装开发依赖时，先确认测试命令能给出明确的缺失依赖信息。
2. 若当前环境已有 pytest，运行全部离线测试并要求通过。
3. 使用 Python AST 解析所有源码和测试，避免生成字节码。
4. 检查 Git 状态，确认不再跟踪 `__pycache__` 或 `.pyc`。
5. 扫描文件名，确认没有新增 `.env`、密钥或凭据文件。

## 完成标准

- 任务根目录存在 `task.md`、`AGENTS.md`、`.gitignore` 和 `requirements-dev.txt`。
- `tests/` 至少覆盖路由、计算器、分块和检索四类离线行为。
- Git 不再跟踪 Python 字节码和缓存目录。
- 所有可运行的离线验证通过；无法运行的验证必须明确记录环境原因。
- Git 差异仅包含本设计范围内的工程化文件与缓存索引清理。

## 后续工作

业务缺陷应在下一阶段逐项采用失败测试、最小修复、回归验证的方式处理，不与本轮工程骨架改动混合。
