# QAgent 双语 README 设计

## 目标

把项目说明从“通用 Agent”修正为与当前实现一致的“带规则路由、简单工具和基础 RAG 的轻量 Chatbot 原型”，同时提供结构对齐、可独立阅读的中文和英文 README。

## 文件结构

- `README.md`：完整英文版，作为 GitHub 默认入口。
- `README.zh-CN.md`：完整中文版，面向项目所有者和中文读者。
- 两个文件标题下方互相链接：`English | 简体中文`。

两个版本必须共享相同章节顺序和事实内容。代码块、命令、路径、路由名称和配置项保持一致；自然语言分别使用英文和简体中文。

## 项目定位

README 必须明确：

- QAgent 当前是轻量 Chatbot 原型，不是自主 Agent。
- 它通过确定性的关键词规则选择 `calculator`、`math`、`outline`、`document_qa` 或 `general_qa`。
- 每次请求只执行一个预定义分支，没有模型自主规划、多步工具循环、人工审批、持久化执行或任务恢复。
- 项目名 QAgent 保留，代表未来可演进方向，不代表当前已具备完整 Agent 能力。

## 事实边界

README 只描述当前仓库已经实现并可验证的能力：

- 普通知识问答
- PDF、TXT、Markdown 上传与文本提取
- 固定字符窗口分块
- 字符/关键词检索和总结回退
- 简单 AST 白名单计算器
- 数学解释、固定模板提纲
- 最多 8 条消息的内存内短期历史
- Streamlit UI
- 7 个测试文件、17 个离线测试

下列内容只能出现在限制或未来路线中，不得写成已有能力：

- Embedding、向量数据库、BM25、混合检索、reranker
- 来源引用和 RAG 质量评测
- 持久化会话、流式输出、重试和可观测性
- 模型驱动的工具选择、多步 Agent Loop、人工审批
- 多用户权限、生产级文件安全和部署能力

## Router 展示方式

README 以表格说明当前优先级：

1. 包含“计算”或算术符号 → `calculator`
2. 包含“积分、导数、极限” → `math`
3. 包含“提纲”或 `outline` → `outline`
4. 已加载文档且命中总结关键词 → `document_qa`
5. 已加载文档且出现 `pdf` 或“文档” → `document_qa`
6. 其他情况 → `general_qa`

同时说明规则路由透明、快速、可测试，但对改写、歧义和未列关键词不稳健。

## RAG 展示方式

README 必须避免笼统声称“语义 RAG”。准确流程为：

```text
文件上传 → 文本提取 → 固定字符分块 → 字符/关键词评分 → 上下文截断 → LLM 回答
```

说明 PDF 不保留页码元数据，chunk 是裸字符串，答案没有引用，`rag/index.py` 为空。

## 安装与安全

- 使用 `python -m pip install -r requirements-dev.txt` 安装完整开发环境。
- 使用 `OPENAI_API_KEY` 环境变量，不在 README 中放置可复制的真实或疑似真实值。
- 使用 `streamlit run app.py` 启动。
- 使用 `$env:PYTHONDONTWRITEBYTECODE = "1"` 和 `python -m pytest` 测试。
- 提醒上传文件、私有文档、日志、缓存、`.env` 和 `docs/private/` 不应提交。

## Router 优化建议的交付边界

README 完成后，向用户单独提供 Router 优化分析，不在本轮修改 `agent/router.py`。分析按四个层级展开：

1. 规则整理与数据驱动配置
2. 优先级、歧义和置信度处理
3. 规则与 LLM 分类器的混合路由
4. 当真实需求出现时升级为结构化工具调用或受控 Agent Loop

建议以离线意图数据集和混合路由作为中期目标，避免直接把所有输入交给 LLM 分类。
